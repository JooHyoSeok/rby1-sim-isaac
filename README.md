# RBY1 비주얼 서보잉 pick & place (Isaac Sim)

Rainbow Robotics **RB-Y1**을 NVIDIA Isaac Sim에서 카메라만 보고 상자를 집어서 원하는 위치에 내려놓게 만든 프로젝트야. DGIST *Intelligent Robot Manipulation* 수업의 카메라-로봇 캘리브레이션, 포즈 추정, 비주얼 서보잉 과제를 RBY1 시뮬레이터 위에서 해보려고 [RainbowRobotics/rby1-sim-isaac](https://github.com/RainbowRobotics/rby1-sim-isaac)를 fork해서 만들었어. 시뮬레이터 본체와 SDK 연동은 upstream 그대로고, 이 fork가 얹은 것만 아래에 적었어. (upstream README는 [docs/UPSTREAM_README.md](docs/UPSTREAM_README.md)에 그대로 있어.)

## 이 fork가 하는 일

- **카메라**: 고정 스테레오 2대와 양손 손등 카메라, 손에는 빨간 구, 상자 3개(파랑·초록·노랑)에는 각자 색 구 landmark를 달았고, 영상과 관절 상태가 시뮬 타임스탬프와 함께 ROS 2 토픽으로 나가.
- **인식**: 스테레오 삼각측량으로 색깔별 상자 포즈를 구해(오차 1~3mm). 코드는 numpy만 써. 쌓은 상자는 맨 위 landmark가 가려져도 3개만 보이면 돼.
- **하이브리드 비주얼 서보잉**: 스테레오로 상자 위치를 대략 잡고, 마지막 정렬은 손등 카메라 영상으로 닫아. 위치 제어와 캘리브레이션이 남기는 정상상태 오차를 영상이 직접 지워.
- **연속 제어**: 20Hz 루프 하나가 목표를 계속 밀어서 SDK 명령 스트림으로 보내. "움직이고 → 멈추고 → 다시 측정"이 없어.
- **전신 IK**: 몸통까지 같이 푸는 Cartesian 명령(rby1 core). 몸통을 접어서 어깨를 낮추고 팔을 굽혀서 일반 높이 테이블에 닿게 했어.
- **충돌 형상**: upstream USD는 손목 링크와 그리퍼에 충돌 형상이 없어서 손이 물체를 통과해. 시작할 때 코드로 손가락에 충돌 형상과 마찰을 붙여(USD는 안 건드려).
- **통합 관제 GUI (Qt)**: 카메라 4개, 위에서 본 장면 지도(상자, 놓을 위치, 테이블을 드래그로 이동), 관절 상태, pick / place / pick and place / home / ABORT.
- **RViz**: URDF(USD에서 추출, 그리퍼 포함)와 TF, 테이블과 상자 마커.

## 실행

필요한 것: NVIDIA GPU와 드라이버, Docker와 nvidia-container-toolkit, 시뮬 이미지 `rainbowroboticsofficial/rby1-sim-isaac:0.10.7-a_v1.2-isaac6.1.0-r1`, **ROS 2 Jazzy 컨테이너**(이름 `intelligent-robotic-manipulation`, `--network=host`, python3와 numpy와 OpenCV 포함: 인식 노드가 여기서 돌아), 호스트의 `/usr/bin/python3`에 PyQt5와 ROS 2 Jazzy(`rclpy`).

```bash
examples/gui/run_gui.sh          # 시뮬, 인식 노드, 실행기, 관제 GUI를 한 번에 (창을 닫으면 전부 정리)
examples/vservo/run_demo.sh      # GUI 없이 한 번: 집어서 들어올리고 결과를 시뮬 정답으로 확인
```

켜는 데 약 2분 걸려(시뮬 부팅). 켠 뒤에는 터미널이나 스크립트, 언어 모델이 같은 실행기를 부를 수 있어:

```bash
examples/gui/rbyctl.py scene                   # 보이는 상자(위치, 어느 상자 위에 있는지), 로봇 상태, 놓을 수 있는 빈 자리
examples/gui/rbyctl.py stack green blue yellow # 아래부터 순서대로, 첫 상자는 제자리
examples/gui/rbyctl.py unstack                 # 쌓은 걸 풀기: 맨 위 상자부터 빈 자리(가능하면 처음 자리)에 내려놓기 (시뮬에서 확인)
examples/gui/rbyctl.py move blue right         # 파란 상자를 집어서 빈 자리(right | left | near | far | center)에 놓기
examples/gui/rbyctl.py pick yellow             # place, place-on, home, abort ... 은 --help
```

말로도 시킬 수 있어. 언어 모델(`claude -p`, 기본 Haiku 5.5, 계획이 틀리면 Sonnet 5.5)이 보이는 상자 상태(텍스트)를 보고 계획을 JSON으로 짜고, 실행기가 서보잉으로 해. 모델은 명령당 한두 번만 불리고 이미지는 안 보내(한 번에 약 4~6초, 정가 기준 $0.0003~0.0004). 서보 루프(20Hz)에는 모델이 없어:

```bash
examples/llm/planner.py "상자 3개 쌓아"                           # 계획을 세우고 바로 실행
examples/llm/planner.py "stack all boxes, blue at the bottom" --scene default --dry-run   # 시뮬 없이 계획만 보기
```

GUI에도 "tell the robot" 입력창이 있어(같은 플래너). GUI에서는 이렇게 써(GUI의 pick은 파란 상자를 집어):

1. 지도에서 주황 상자나 파란 "place here" 표시를 **끌어서** 옮겨. 팔이 닿을 수 있는 곳(초록)으로 자동으로 붙어. 상자 위에서 휠을 돌리면 방향이 돌아가.
2. `pick`을 누르면 로봇이 준비 자세를 잡은 뒤 서보잉으로 상자를 집어서 들어올려. `place`는 들고 있는 상자를 파란 표시 위치에 내려놓고, `pick and place`는 둘을 이어서 해.
3. `ABORT`로 진행 중인 작업을 멈춰(설계상 동작 중에도 멈추게 만들었는데, 시뮬에서 충분히 검증하진 못했어. 아래 한계 참고).

컨테이너 이름이나 시뮬 이미지가 다르면 `examples/gui/run_gui.sh`와 `examples/vservo/run_demo.sh` 위쪽의 `ROS=`와 `IMAGE=` 값을 고치면 돼.

## 목록에 없는 동작: 도구 쓰는 모델 (`examples/agent/`)

"손 흔들어", "고개 끄덕여", "머리를 오른쪽으로 돌려"처럼 정해진 기술에 없는 요청은 플래너가 `improvise`로 넘기고, 두 번째 모델(Sonnet 5.5)이 도구를 써서 직접 설계해:

```bash
examples/agent/improvise.py "손 흔들어" --offline   # 로봇 없이: 설계와 안전 검사까지만 (정가 환산 약 $0.02~0.05, 30초 안팎)
examples/agent/improvise.py "고개 끄덕여"           # 실제 로봇 (run_gui.sh가 켜져 있어야 해)
```

- 모델이 쓰는 도구는 `robot_tools.py`뿐이야(`claude -p --tools Bash --allowedTools "Bash(<그 파일>:*)"`): `state`(관절각, 손 위치), `limits`(움직일 수 있는 관절, 범위, 속도), `fk`(관절값을 바꾸면 손과 머리가 어디로 가나), `check`(안전 검사만), `move`(검사 후 실행), `save`/`play`/`skills`(잘 된 동작 저장).
- 순서는 모델이 정해: 저장된 동작 확인 → 상태와 한계 → `fk`로 관절이 하는 일을 시험 → 궤적 작성 → `check`가 알려준 위반 고치기 → `move`.
- **안전은 코드가 지켜**(`safety.py`): 양팔, 머리, 몸통 요만 움직이고(두 팔이 15cm 안으로 가까워지거나 손이 몸 중심을 넘으면 거절), URDF 한계에서 5.7° 여유, 관절 속도 한계, 궤적 길이, 경로를 3° 간격으로 훑어서 팔꿈치, 손목, 손이 테이블, 바닥, 몸 중심, 상자에서 떨어져 있는지. 실행기가 움직이기 전에 한 번 더 검사해(클라이언트를 믿지 않아). 시뮬 USD에 손목과 그리퍼 충돌 형상이 없어서 이 규칙은 일부러 넉넉하게 잡았어.
- 이 모델 호출은 `--strict-mcp-config`가 꼭 필요해. 없으면 플러그인의 MCP 서버가 도구를 한 번 쓴 뒤부터 호출마다 컨텍스트에 약 27만 토큰을 끼워 넣었어(정가 환산 $1.29가 $0.047로 줄었어).
- **바퀴 이동**(`drive`, `examples/gui/base_motion.py`): 앞뒤 30cm, 회전 90°까지 한 번에, 바퀴 회전량으로 위치를 재면서 20Hz로 속도 명령을 보내(0.3초 유효라 프로그램이 죽으면 서). 테이블과 팔을 검사해서 부딪히면 거절해. 몸이 어디에 서 있든 집기, 쌓기, 팔 동작이 돼(스테레오가 본 세계 좌표의 상자를 시뮬의 몸 위치 정답으로 몸 좌표계로 바꿔서 쓰고, 테이블은 세계 좌표 그대로 검사해). `rbyctl.py drive --forward 0.2 --turn -30`, `--home`으로 돌아와.
- **시뮬에서 바퀴를 굴려본 결과**: 직진은 정확해(5cm 후진 명령에 시뮬 정답 -0.058m, 오도메트리 -0.058m, 바퀴 부호 `FORWARD_SIGN=-1`도 맞아). 회전은 바퀴 두 개가 정상으로 돌아가는데(±2rad) 몸은 제자리 회전을 거의 못 해(명령의 10~30%, 방향에 따라 다르고 몸 원점이 20~60cm 휘둘러져). SDK 명령이든 바퀴 관절 직접 명령이든 같아서 시뮬의 접지 물리 쪽 문제로 보여. 그래서 회전은 시뮬 정답 위치로 피드백하며 천천히 돌고, **정확한 제자리 복귀는 못 해**(그래서 복귀를 강제하지 않고 정답 위치로 좌표를 변환하는 방식으로 풀었어). 휠 오도메트리는 회전에서 두 배쯤 틀려서 시뮬에서는 정답 위치를 직접 써.
- 시뮬에서 확인한 것: FK는 시뮬 값과 맞아(내린 자세 손끝 1mm, 왼팔 궤적 뒤 손목 4mm 이내). 왼팔과 양팔 관절 동작이 실제로 돼(왼손 흔들기, 모델이 설계한 "양손을 위로 번쩍": 손목 높이 1.56m와 1.61m). 몸이 (0.005, -0.047)로 밀려난 채로 쌓기와 쌓인 맨 위 상자 집기, `place_on`이 돼(시뮬 정답으로 xy 1mm). 몸이 4.6cm만 밀려도 노랑 상자가 오른팔 한계(0.50m)를 넘어서 거절됐던 문제는 왼팔로 집기를 넣어서 풀었어.
- **왼팔 집기, 놓기, 팔 바꾸기**(시뮬 정답으로 확인): 노랑을 왼쪽 (0.62, 0.22)에 두면 `pick yellow`가 "the left arm takes the yellow box"로 왼팔을 골라서 집고(서보 도착 오차 1mm), `place 0.64 0.14`로 (0.625, 0.141)에 내려놔(목표보다 x로 1.5cm쯤 덜 가: 닿는 한계 근처에서 생기는 오차로 보고 있어). 이어서 `stack green blue`를 시키면 오른팔이 "park the left arm"으로 왼팔을 접어두고 파랑을 초록 위에 올려(시뮬 정답으로 xy 0.3~0.4mm 어긋남, 높이 0.84). 테이블 앞 모서리(x 0.58)에서 4cm 안쪽(x 0.62)보다 가까운 곳에 `place`를 직접 시키면(`rbyctl`은 안 막아) 상자가 모서리에서 미끄러져 바닥으로 떨어져: 플래너와 GUI는 `check_pose`로 막아.
- **몸 위치 값이 팔 동작 중에 튀어**: 시뮬이 주는 로봇 위치(정답)가 팔을 움직이는 동안 몇 cm에서 17cm까지 튀어(TF와 FK는 가만히 서 있다고 해). 그래서 바퀴를 굴리는 동안만 그 값을 믿고, 멈춘 뒤에는 마지막 값을 붙잡고 있어(`_latched`). 팔 동작 중에 몸을 시뮬에서 고정시키는 시도는 집기만 망가뜨려서 뺐어.
- **캘리브레이션 구는 기본으로 꺼 뒀어**: 테이블 위 빨강·파랑·노랑 구(HW7 캘리브레이션 표적)가 왼손 손등 카메라에서 상자 landmark와 헷갈려서 집기가 4cm 빗나갔어. 그 구가 필요하면 `RBY1_CALIB_TARGET=1`로 켜(`docker/run.sh`가 컨테이너로 넘겨줘).

## 어떻게 동작하나

```
 시뮬 (Isaac Sim, 컨테이너)                        ROS 2 컨테이너                 호스트
 ───────────────────────────                      ──────────────────            ──────────────────
 카메라 4대, 관절 상태, GT  ── ROS 2 토픽 ──────▶  인식 노드                     관제 GUI (Qt)
 장면 명령 서버 (UDP 5110) ◀──────────────────────────────────────────────────── 상자/테이블 이동
 실행기 서비스 (UDP 5120) ◀─────────────── pick / place / abort ────────────────  버튼
   └ 20Hz 서보 루프 → SDK 명령 스트림 → rby1 core (전신 IK) → 로봇
```

- 상자 포즈: 스테레오 두 영상에서 상자 색 구의 중심을 삼각측량하고, 랜드마크를 강체 변환으로 맞춰(Arun SVD). 같은 줄에 놓인 구 두 개는 짝이 두 가지로 맞아서, 짝을 하나로 정하지 않고 강체 배치에 맞는 쪽을 골라.
- 정렬: 손등 카메라가 본 랜드마크로 상자 중심을 손 좌표계에서 구하고, 영상이 찍힌 시점의 손 위치를 써서 지연을 보정한 뒤 도구선 위로 끌어와.
- 자세한 설계 이유는 각 파일 위쪽의 설명(docstring)에 적어놨어.

## 측정한 결과 (시뮬레이터)

- 스테레오 상자 위치: 1~3mm 오차(랜드마크 3개로 충분).
- 스테레오 추정을 일부러 **(y +2cm, z +5cm) 틀리게** 줬을 때: 위치 제어만 쓰면 손가락이 허공을 잡고 실패하지만, 영상 보정을 켜면 손 좌표계에서 본 오차가 46.9mm에서 0.6mm로 줄고 3.7초 만에 도착해서 집어 올려(손끝 속도는 0에서 7.3cm/s까지 올라갔다 부드럽게 내려와, 중간에 멈추지 않아).
- pick and place: 목표 (0.633, -0.256)에 놓았더니 (0.623, -0.255)에 상자가 똑바로 섰어(x 방향 약 10mm 오차).
- 상자 3개 쌓기(`rbyctl.py stack green blue yellow`, 약 3분): 시뮬 정답으로 초록 z 0.76, 파랑 0.84, 노랑 0.92(8cm씩 정확), 세 상자의 x, y 어긋남은 4mm 이내. 로봇이 스스로 잰 값은 파랑이 초록 위에서 x -9.9mm, 노랑이 파랑 위에서 (-3.2, +2.1)mm. 놓기 직전 정렬이 잰 오차는 2~3mm였는데 놓은 뒤에는 최대 10mm 벌어져서, 놓는 순간 상자가 밀리는지 든 상자 측정에 치우침이 있는지는 아직 몰라.

## 최종 과제(혼합 부품 조립) 준비: 시뮬 없이 확인한 것 (`examples/assembly/`)

수업 9주차 슬라이드의 최종 과제는 상자 쌓기가 아니라 양팔 조립이야: 짝이 맞는 부품 한 쌍을 찾고, 팔마다 하나씩 집고, 든 채로 정렬해서 끼우고, 완성품을 상자에 넣어. 부품은 원형, 사각, D형, 키 있는 커넥터, 이중 핀 다섯 종류고 전부 축 방향으로 끼워. 아래는 시뮬레이터 없이(모의 영상, FK, 충돌 모델로) 확인한 것이고, 시뮬에서는 아직 안 돌렸어. 시험은 `test_assembly.py`(7개).

- **짝 맞춤 수학**(`assembly.py`): 부품마다 맞닿는 면 중심에 원점, 면 밖으로 +z, 열쇠 쪽이 +x. 두 부품을 한 카메라에서 본 자세로 `F_T_M = inv(C_T_F) C_T_M`을 구하면 카메라와 몸 사이 변환이 상쇄돼. 여기서 옆 어긋남, 깊이, 축 기울기, 축 둘레 회전을 뽑고 그걸 없애는 보정을 줘. 회전 대칭은 종류별로 달라(원형은 아무 각도, 사각은 90°마다, 나머지는 한 방향뿐).
- **부품 모델**(`parts.py`, 중간 과제용 원통과 구멍, 최종 CAD가 오면 바꿔): 몸통 반지름 22.5mm 길이 70mm, 구멍 반지름 10mm 깊이 30mm, 핀 길이 30mm, 기본 틈새 2mm. 구멍은 상자 16개로 둘러싼 고리야(속이 빈 몸통은 볼록 충돌체 하나로 못 만들고, 움직이는 물체는 삼각형 메시를 못 써). 이 고리 모델과 "축이 입구와 깊은 곳에서 틈새 원 안에 있으면 들어간다"는 식이 474개 무작위 자세에서 같은 답을 내.
- **부품 인식**(`part_perception.py`): 부품마다 색이 다른 구 4개(반지름 6mm, 3개는 뒤쪽 고리, 1개는 맞닿는 면 옆에 띄움)를 삼각측량하고, 어느 구가 어느 landmark인지는 모든 배정을 강체 맞춤해서 골라. 틀린 배정은 어떤 3개나 4개 조합으로도 rms 6.1mm 이상이라(잡음 0.5mm) 하나만 가려져도 자세가 하나로 정해지고, 모호하면 거절해. 납작한 고리만 쓰면 180° 뒤집은 배정이 1mm로 맞아서 모호했어. 머리 카메라는 부품에서 0.3m라서 반지름 12mm 구는 영상에서 서로 붙어 한 덩어리가 됐고(그래서 6mm), 구 위치는 가정이야. 가짜 영상으로 확인: 구가 다 보이면 두 부품 상대 자세가 0.7mm / 0.5°, 부품마다 구 하나씩 다른 영상에서 가려져도 2.5mm / 1.0°.
- **머리 스테레오**(`head_camera.py`, 달 위치는 가정): 0.4m 앞에서 두 부품의 상대 자세가 0.7mm / 1.0°야(픽셀 잡음 0.2). 머리와 몸통 관절을 1°씩 틀어도 상대 자세는 0.9mm / 0.9°로 그대로인데, 절대 위치는 **39mm** 틀어져. 슬라이드 10쪽 그대로야: FK로 구한 카메라 자세로 절대 위치를 찍어서 집으면 빗나가고, 부품과 손 표식을 같은 영상에서 상대로 재야 해. 시뮬의 머리 카메라는 `RBY1_HEAD_CAM=1`로 켜(`src/rby1_vision.py`). 시뮬에서 확인했어: 머리를 0.5 rad 숙이면 FK로 예측한 구 위치가 영상 속 구와 1px 안으로 맞고(달 위치와 링크 경로가 맞아), 이 카메라로 상자 위치를 삼각측량하면 시뮬 정답과 초록 3mm, 노랑 1mm 차이야.
- **끼워질 확률**(`python3 examples/assembly/assembly.py`): 옆 어긋남과 기울기는 합쳐지니까(기울기는 깊은 곳에서 축을 `깊이 x 기울기`만큼 더 옮겨) 따로 보면 안 돼. 둘이 같이 틀릴 때 정렬 오차가 1mm / 1°(1시그마)면 반지름 틈새 1, 2, 3mm에서 약 32, 79, 97%야. 정렬 오차가 0.5mm / 0.5°면 틈새 1mm에서 80%, 2mm에서 거의 100%야.
- **관찰, 이동, 재관찰 반복**(`align_sim.py`, 가짜 영상 + 팔 오차 모의): 시작이 8mm / 3° 틀어져 있고 팔이 명령보다 10% 덜 또는 더 움직이고 0.3mm / 0.3° 잡음이 있을 때, 한 번 볼 때 영상 5장을 평균하면 틈새 1, 2, 3mm에서 끼워진 비율이 픽셀 잡음 0.2에서 73, 100, 100%, 0.5에서 18, 75, 97%야. 한 장만 쓰면 0.2에서 12, 77, 100%야. 접촉 동역학, 랜드마크 중심의 치우침, 손에서 부품이 미끄러지는 건 안 넣었어.
- **양손이 만나는 자세**(`meet_study.py`, 몸통은 쪼그린 자세로 고정, 역기구학 + 관절 한계): 부품 축을 y로 두고 각 손이 맞닿는 면에서 3cm 뒤를 잡는 자세로, 손끝이 앞(x)을 향하고 손가락이 위아래로 닫히면 x 0.42~0.48, z 0.9~1.1m 근처에서 닿아. 다만 그때 두 팔의 팔꿈치와 팔뚝이 6cm밖에 안 떨어져서 부딪힐 위험이 크고(`safety.py`의 15cm 규칙도 못 맞춰), 손끝을 안쪽으로 30° 돌리면 간격이 30cm로 벌어지는데 닿는 곳이 x 0.48(z 전체)와 x 0.42, z 0.9로 줄어. 몸통을 고정하고 시작 자세 6개로만 풀었으니 "안 닿는다"는 증거는 아니야.

## 양팔 동작 (`rbyctl.py meet`, 시뮬 확인)

- **빈손 `meet`**: 두 손이 맞닿는 면 앞(x 0.48, 높이 1.0m)으로 동시에 가서 도착 오차 0.1~0.4mm, 방향 오차 0°로 닿아. 두 팔의 팔꿈치·팔뚝 간격은 9cm로 오프라인 연구가 예측한 값과 같았어. `unmeet`으로 돌아와.
- **두 번째 상자 집기**: 노랑을 왼팔로 집어 든 채로 `pick blue`를 하면 오른팔이 집어(서보 도착 오차 1mm 안). 이게 되려면 고칠 게 둘 있었어. 한 팔이 상자를 들고 있으면 다른 팔을 준비 자세로 보내는 관절 명령이 로봇에서 "Canceled"로 취소됐는데, 로그를 보니 앞선 스트림의 제어권이 아직 안 풀렸을 때(우선순위가 같음) 새 명령이 들어간 탓이라 스트림을 끊고 0.4초 기다리게 했어.
- **상자를 든 채 `meet`은 아직 안정적이지 않아**: 손이 상자를 든 채 90° 돌아야 하는데, 세 번 중 두 번은 오른손 상자가 돌아가는 도중에 떨어졌고(한 번은 만난 뒤 상자 중심 사이 9cm, 높이 0.99m로 잘 들고 있었어), 왼손 상자는 버티지만 6초에 2cm쯤 서서히 미끄러졌어. 손을 반대 방향으로 돌리는 자세(닫힘 방향 +z)는 방향 오차가 73°로 안 닿았고 오른손이 왼쪽으로 가로질러 가서 뺐어. `unmeet`은 부품끼리 부딪히지 않게 손을 10cm 벌린 뒤 되돌리게 고쳤는데, 상자를 든 채로는 아직 확인 못 했어.

## 한계와 아직 안 한 것

- **닿는 범위가 좁아**: 팔이 짧아서 기본 테이블에서는 상자가 설 수 있는 위치가 x 0.62~0.65 근처 한 줄뿐이야. 테이블을 로봇 쪽으로 당기면 넓어지지만, 준비 자세로 가기 전에는 테이블 앞 모서리가 x 0.57보다 가까우면 팔꿈치가 걸려(GUI가 막아줘). 그래서 기본 테이블에서는 상자 3개를 12cm 간격 한 줄(x 0.62)로 놓으면 그 띠가 거의 다 차서 `rbyctl.py move`로 옮길 빈 자리가 없고, 쌓기는 되지만 옮기기는 테이블을 당긴 뒤에나 쓸 만해(당긴 테이블은 시뮬에서 검증 전).
- **팔 선택**: 집기, 놓기, 쌓기는 양팔로 돼. 상자마다 "어느 팔이 손을 가장 편하게 두나"(어깨에서 손목까지 거리가 닿는 범위의 가운데에서 얼마나 가까운가)로 팔을 골라(`best_arm`, 플래너도 장면에서 봐). 다른 쪽 팔은 옆에 내려 접어두고, 팔을 바꿀 때마다 한 번 준비 자세로 가야 해서 20초쯤 더 걸려. 한쪽 팔로 집고 다른 쪽 팔로 놓는 건 안 돼(들고 있는 팔이 놓는 곳에도 닿아야 해서, 닿는지 미리 같이 검사해). 기본 테이블에서는 상자 3개가 전부 오른팔 쪽 띠에 있어서 왼팔은 일이 없어: 왼쪽에 상자를 두면 왼팔이 집어(`rbyctl.py set-box yellow 0.60 0.22`). 오른팔은 y -0.34~-0.10, 왼팔은 +0.10~+0.34만 닿고 가운데(-0.10~+0.10)는 둘 다 안 닿아. 시뮬에서 확인한 건 왼팔 집기와 놓기, 그 뒤 오른팔로 바꾸기까지야. 오른팔에서 왼팔로 바꾸기, 왼팔로 쌓기, 말로 시킨 팔 선택은 안 돌려봤어.
- 물체는 5x5x8cm 상자 3개야. 그리퍼 방향이 고정이라 상자를 ±30°보다 많이 돌리면 못 집어.
- 시뮬레이터에서만 확인했고 실제 로봇에서는 안 돌려봤어. 영상 지연(0.12초)과 게인은 시뮬에 맞춰 정한 값이야.
- GUI에서 `ABORT`, 테이블을 당긴 뒤 집기, `home`은 아직 시뮬에서 충분히 검증하지 못했어.
- 상자 쌓기는 시뮬에서 한 번 끝까지 성공했을 뿐이야(반복 성공률은 아직 몰라). `move`(빈 자리로 옮기기), 다른 쌓는 순서, 쌓는 도중 ABORT는 시뮬에서 안 해봤어. `unstack`은 한 번, 말로 시킨 쌓기와 "가운데만 빼줘"는 각각 한 번씩 성공했어.
- 카메라-로봇 캘리브레이션(eye-to-hand, hand-eye 풀이)과 ACT 학습은 아직 안 만들었어.

```bash
/usr/bin/python3 examples/vservo/test_boxes.py                            # 색깔별 상자 3개 인식, 쌓인 상태 포함 (가짜 스테레오 영상)
/usr/bin/python3 examples/assembly/test_assembly.py                        # 짝 맞춤, 부품 모델, 부품 인식, 머리 스테레오, 정렬 반복 (모의)
```
